# Mercury Marketplace — Business Model

## Platform vs inventory

| Actor | Owns | Does not own |
|-------|------|--------------|
| Mercury | Marketplace software, discovery, workflows, trust architecture | Parts, services, certificates as inventory |
| Seller org | Catalog offerings, pricing, availability, fulfillment evidence | Platform rules / tenant isolation |
| Buyer org | Purchase requests, quotes, orders, reviews | Seller inventory |

## Revenue architecture (future)

Architecture supports (not implemented as billing):

1. Marketplace subscription tiers for seller orgs
2. Transaction / success fees on completed orders (payment gateway future)
3. Featured placements / sponsored search (fraud-detection ready)
4. Premium verification workflows (document verification ready — not regulatory approval)

## Value propositions

- **Sellers:** global aviation reach inside AEOS tenants that already operate fleet/MRO/logistics.
- **Buyers:** one catalog for parts, repairs, cal, tools (sale/rental), training, jobs, consulting.
- **Mercury:** stickiness across ecosystems (Program 12) without becoming a distributor.

## Disclaimers (mandatory)

- Verification badges ≠ authority approval or certificate authenticity claim.
- Certificate JSON fields store references / readiness metadata, not legal airworthiness assertions.
- Careers AI matching and product AI ranking are metadata hooks only until advisory AI is productized.
